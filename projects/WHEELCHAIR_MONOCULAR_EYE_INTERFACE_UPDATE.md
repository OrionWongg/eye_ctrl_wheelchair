# 最新单目眼动接口接入说明

日期：2026-10-14。

按用户最新要求，轮椅侧直接使用 EYETLE 现有接口，不修改眼动检测、三维建模、标定或眼动侧交互代码。

## 修改

- 取消轮椅启动器注入的双目选项，以及前一轮准备增加的估计方法、参考文件解析逻辑。
- 调用现有 `EYETLE/start_ritnet.sh`，相机与算法配置完全采用该脚本当前默认值；目前为左眼单目、3D 眼球估计。
- 用户显式提供的眼动参数原样转交。轮椅侧只启用检测器已经支持的 `--publish-stamped`，统一 ROS domain，接收现有 `/eye_tracking/samples`。
- 原有方向事件、双眨眼确认、长闭眼/无效输入停车和公共避障链路保持不变。`valid=false` 时不能因水平值或闭眼标志而授权运动。
- 眼动中心参考仍由 EYETLE 管理，轮椅侧不读取、转换、覆盖或重新生成用户标定。

## 使用

先关闭旧仿真和重复的眼动检测进程，然后运行：

```bash
cd ~/projects/EYETLE
./start_eye_wheelchair.sh
```

无需 `--eyes both`。单目建模、正前方确认和当前状态提示，直接按照 [EYETLE 最新说明](EYETLE/GAZE3D.md) 操作。模型未稳定或参考未就绪时，眼动输出无效，轮椅保持停车；恢复有效数据不会自动恢复旧运动。

## 验证边界

轮椅启动器回归检查默认不注入检测参数，并覆盖单目参数、中心文件、显式 legacy 参数以及其他模型参数的原样传递；眼动适配器沿用已有协议回归测试。本次没有再运行或修改眼动算法，也没有重新采集中心参考。

用户澄清前的隔离双目接口测试已经退出；其 91 条无效样本仅证明旧验证流程不会把未确认参考误当作运动授权，不作为最新版单目硬件验收证据。
