> 当前恢复方式已改为暂停后单次短眨眼（60～400ms），以下注视方案仅作为历史设计记录。

# 减少重复眨眼的状态机改进建议

日期：2026-10-13。本文保留研究与设计依据。本轮已实现取消正常行驶的5秒限时、保持控制模式的暂停、注视恢复及反馈进度条；海龟方向控制方式调整和二维注视按钮仍是后续建议。当前操作见 [RITNET.md](../RITNET.md)。

## 当前疲劳的来源

海龟控制器只有 STOPPED/FORWARD，前进超过 5 秒就停止。Gazebo 轮椅眼动状态机虽然区分 DISARMED/ACTIVE/BLOCKED/INVALID，但 `max_motion=5.0` 同样会撤销控制授权；长闭眼及输入丢失后也需要新的双眨眼。因此重复眨眼不是检测模型的要求，而是当前控制规则造成的。

海龟的一秒转向脉冲也需要反复回正再触发。轮椅仿真的眼动模块已经采用 250 ms 的方向停留确认，不能把这两个控制器当成完全相同的状态机。

## 查到的已有做法

1. **Tobii Dynavox：注视停留选择与暂停/恢复。** 注视目标一段时间后选择，停留时间可调；提供单独的暂停功能，并可要求先移开视线再重新选择以防连发。这是桌面辅助交互，不是车辆自动恢复行驶的验证依据。
   - [注视选择与防重复选择](https://www.tobiidynavox.com/blogs/support-articles/what-selection-options-are-available-in-windows-control)
   - [暂停与恢复眼动交互](https://www.tobiidynavox.com/blogs/support-articles/how-do-i-make-a-button-to-pause-and-unpause-gaze-interaction-in-communicator)
2. **Sensors 2020：开关与方向分开。** 该近眼摄像头轮椅研究采用左眼眨动切换启动/停止，启用后按注视方向输出运动，另设超声传感器停车。可借鉴“模式保持”，不必照搬单眼眨动手势。
   - [An Intelligent and Low-Cost Eye-Tracking System for Motorized Wheelchair Control](https://www.mdpi.com/1424-8220/20/14/3936)
3. **ETRA 2020：按钮、连续控制、目标点导航。** 研究比较了注视按钮、连续注视转向和目标点导航；VR 实验中目标点导航表现最好、最受偏好，连续控制次之。但真实轮椅参与者对必须低头看地面感到不适，说明减少输入次数不能以不自然的注视姿势为代价。
   - [Exploring Eye-Gaze Wheelchair Control，DTU 作者机构页面](https://orbit.dtu.dk/en/publications/exploring-eye-gaze-wheelchair-control/)

这些项目没有共同的唯一标准状态机。下面的具体状态、手势和时间参数是针对当前项目的设计建议，不是直接复现上述论文，也不是经过验证的轮椅控制参数。

## 推荐方案：控制模式保持，停车原因分开

| 状态 | 运动输出 | 转换方式 |
|---|---|---|
| 未启用 | 零速度 | 首次明确确认进入控制模式；可先沿用一次双眨眼 |
| 已启用、暂停 | 零速度 | 新的注视恢复动作完成后进入行驶；重新睁眼或持续看正中本身不启动 |
| 已启用、行驶 | 按有效注视方向运动 | 主动暂停或检测中断进入暂停；安全系统阻断进入故障阻断 |
| 故障阻断 | 零速度且禁止眼动启动 | 故障解除、底层报告允许重新授权后回暂停；仍需新的恢复动作 |

任何状态发生急停、相机断开、过期输入或底层状态失联，都不能继续输出旧运动指令。关闭控制模式进入“未启用”；持久化保存的仅是标定，不能在软件重启后自动恢复之前的行驶授权。

### 1. 取消正常行驶时的固定 5 秒停车

在仿真中，将“累计行驶时间到 5 秒即撤销授权”改为“持续收到有效、新鲜的眼动输入和正常的底层状态，才允许继续”。保留现有输入超时检查、故障锁止、碰撞检查及速度限制。不能只删除计时器而忽略底层许可。

这一步最直接减少重复双眨眼。普通自然眨眼不作为启停指令，也不退出控制模式；超出正常眨眼容忍范围或状态不可判断时仍停止运动。

### 2. 主动暂停不等于退出控制模式

先保留长闭眼停车的手势，但其结果改为“已启用、暂停”。睁眼后保持静止，显示“已暂停”。退出控制模式用明确的退出操作区分，不再把所有停止都处理为重新登录控制。

### 3. 恢复用新的注视确认，减少双眨眼

当前只有水平注视信号，没有可靠的屏幕二维注视坐标，因此暂不能声称已经可以通过眼睛精确点击屏幕上的“继续”按钮。

可以先在仿真测试这样的水平手势：

- 进入暂停之后，重新观察到注视离开中心、在一侧稳定约 250 ms；
- 然后回到中心，稳定约 600～800 ms，进度条填满才恢复行驶；
- 中途检测无效则清除该手势，不保留半完成的恢复指令；
- 双眼模式要求双眼有效，底层必须允许重新授权。

这是“离开再回到中心”的显式动作，不是“只要看中间就自动走”。这些时长只是待调试初值；自然环顾仍可能形成类似动作，需要用暂停场景中的误启动率验证。如果此动作仍费力，后续可增加二维标定和独立的注视继续按钮。

### 4. 转向采用短停留确认

海龟模式可改为左/右注视稳定约 250 ms 后转向，回到中心稳定后直行，保留进入/退出阈值差以防抖动。轮椅仿真已经有类似的方向停留逻辑，优先保留并调整体验，不需要重复实现。

持续看侧边转弯与一秒转向脉冲体验不同，应在仿真对比误转向次数和绕障操作负担，不能假设连续转向一定适合所有用户。

## 为什么不建议睁眼后自动恢复行驶

长闭眼可能是用户明确想停车；相机重新看到眼睛也只说明检测恢复，不能证明用户想继续。障碍消失同样不代表可以复用旧的行驶意图。因此恢复检测或解除故障只回到暂停，不直接回行驶。

## 实施顺序与验收

1. 仿真先取消 5 秒例行停车，保留全部有效性和底层安全检查；观察一次进入控制后能否稳定持续操作。
2. 增加保持授权的暂停状态，并把用户暂停、输入异常和底层锁止分开记录。
3. 接入新的注视恢复动作，保留双眨眼作为备选操作；界面显示当前状态、停止原因和恢复进度。
4. 记录每分钟主动眨眼次数、暂停后的误启动次数、恢复成功率/耗时、注视方向误触发和故障停车行为。若后续用于实体设备，仿真测试不能代替实体停车及故障验收。
