## 1. RITnet 对照方案结论

当前默认方案是 **双眼 RITnet + TensorRT 分割、左右眼独立 pye3d 三维眼球估计、一次正前方双眼中心确认**。

RITnet 入口默认 `--eyes both`；可显式指定 `--eyes left` 回到单眼诊断。此次启用已有双眼链路，不改变控制器的手势规则。旧的左/中/右三点标定方案保留，可以切回对照。

新方案已经接入单眼/双眼预览和 ROS 信号发布，支持中心参数保存、启动加载、移位检查及无效输入停车。现场日志已出现 `3D_READY`，但仍有拟合和移位检测波动，不能视为已完成抗镜架移位验证，也不能宣称完全免标定。

**标定状态快照：** 本次检查时，左眼三维中心文件存在，但已标记 `requires_confirmation=true`。必须重新看正前方按 S，采集并保存成功后才能继续复用。此前“保存成功、可复用”的状态已发生变化。

## 2. 硬件与算法流程

- 平台：Jetson Orin，ROS 2 Humble。
- 摄像头：HBVCAM-1914S V44，640×480，按 30 FPS 请求 MJPG 图像。
- 左眼：USB 路径末尾 `4.4.1:1.0-video-index0`，图像旋转 180°。
- 右眼：USB 路径末尾 `4.4.2:1.0-video-index0`，默认旋转 0°。
- 摄像头按 USB 路径识别，避免 `/dev/videoN` 编号变化导致左右眼错配。

```text
眼睛图像
  ↓ 安装方向纠正
RITnet TensorRT 分割瞳孔、虹膜等区域
  ↓ 瞳孔椭圆转换到完整图像坐标
pye3d 自动拟合三维眼球、估计眼球朝向
  ↓ 减去已确认的正前方参考
归一化左/中/右输入 + 眨眼状态 + 有效性
  ↓ ROS
当前选定的海龟或轮椅控制器
```

旧算法使用瞳孔在图像中的横坐标，镜架移动也会改变该横坐标，容易被误认为转眼。新方案尝试利用三维眼球模型区分这些变化，但依赖可靠的瞳孔椭圆、相机几何和足够的视角观测。

相机焦距目前由资料中的对角视场角 80° 推算，约 476.7 像素，尚非实测内参，也没有完成镜头畸变矫正。镜架明显旋转后，相机轴与正前方的关系改变，仍可能需要重新确认中心。

## 3. 建议启动流程

此前快照中右眼尚未保存三维中心。双眼模式必须等待左右眼模型均就绪，再按 S 同时采集两个中心；只有左眼参数时不会输出有效控制。

### 仅预览和记录日志

```bash
cd /home/whill/projects/EYETLE
mkdir -p model-results
./start_ritnet.sh --eyes both 2>&1 | tee model-results/gaze3d-live.log
```

此入口运行检测并发布 ROS 眼动信号，不启动控制器。若同一 ROS 域已有控制器，它仍可能接收这些信号；完全不发布信号的预览可使用：

```bash
.venv/bin/python tools/ritnet_tracker.py --eyes both
```

首次使用或中心被撤销时：

1. 戴稳眼镜，缓慢看左、右、上、下，让模型获得不同角度的瞳孔观测。
2. 等待左右眼均显示 `3D_READY`。初始化需要有效观测，不是简单等待固定秒数。
3. 头朝前、眼睛看正前方，点击预览窗口使其获得键盘焦点，然后按 **S**。
4. 按键后等待 0.4 秒，继续保持正前方，左右眼同时采集 60 个有效稳定样本。
5. 自动保存成功后，中心参考才可用于控制。

三维模式不需要依次按 A/S/D。建模成功后不要求不停扫视，保持正前方不会再因为缺乏视线变化而自动退回初始化。

### 海龟控制

```bash
./start_eye_turtle.sh --ritnet --eyes both
```

海龟沿用首次双眨眼启用、长闭眼约 0.65 秒暂停、睁眼保持停止、再短眨眼一次恢复的逻辑。短眨眼范围为 60～400 ms。正常行驶没有原来的 5 秒强制停止，输入超时和急停保护保留。

### 轮椅仿真

```bash
./start_eye_turtle.sh --gazebo --eyes both
```

**轮椅启动器当前默认是 `directional_intent` 模式**：注视选择正中/左/右，双眨眼确认；长闭眼或跟踪失效停车。不能把海龟的单眨眼恢复规则直接套用到该模式。

如需原 `gaze_joystick` 交互模式：

```bash
WHEELCHAIR_INTERACTION_MODE=gaze_joystick \
  ./start_eye_turtle.sh --gazebo --eyes both
```

不同入口不要同时运行多个摄像头发布程序。关闭预览用 Esc；整套启动器可用 Ctrl+C 退出。

```bash
./start_ritnet.sh --eyes both --center-file state/user-center-3d.json
```

```bash
./start_ritnet.sh --eyes both --gaze-method legacy \
  --calibration-file state/ritnet-calibration.json
```

## 5. UNSTABLE 问题及已完成修复

### 移位触发过于频繁

早期 15 秒诊断出现 16 次移位事件，原实现每次清空眼球模型，阻碍初始化完成。

已改为：初始化期间保留观测；已稳定模型检测到移动后停止有效输出，等待移动结束至少 0.7 秒再执行一次重新拟合。光流排除眼睛区域，并增加空间覆盖和往返一致性检查。移位检测仍可能误报或漏报，需要佩戴验证。

### 正常定睛被误判为尚未建模

原实现持续要求最近 150 帧有足够的视线变化。用户回到中心保持不动后，滑动窗口逐渐失去扫视历史，导致再次等待建模。

已改为首次成功拟合后保留“视角覆盖已满足”的状态，仅在模型重新拟合时清除。新增回归测试验证：扫视建模后持续定睛超过 150 帧仍能保持就绪。

### 日志状态不够具体

原来多种等待原因都显示 `MODEL_WARMUP / SHIFT`。现已拆分：

| 状态 | 含义 |
|---|---|
| `3D_READY` | 当前三维模型通过有效性检查；仍需有效中心参考 |
| `WAIT_EYE_SWEEP` | 初始化视角覆盖不足，需缓慢扫视 |
| `WAIT_MOTION` | 图像运动触发暂时阻断，保持镜架稳定 |
| `WAIT_CENTER_STABILITY` | 三维眼球位置估计尚在波动 |
| `3D_UNSTABLE: model range` | 眼球位置或瞳孔大小等超出模型合理范围 |
| `NO_RELIABLE_PUPIL` | 缺少可靠的瞳孔输入 |
| `CLOSED_WITHOUT_STABLE_MODEL` | 闭眼前没有可沿用的稳定三维状态 |

日志每约 2 秒输出 `GAZE3D` 记录，包含模型置信度、眼球位置、瞳孔直径、位置离散度、视角覆盖及移位次数。模型置信度不等于实际准确率。

## 8. 双眼融合具体逻辑

这里的“双目”指两台近眼摄像头分别观察左右眼，再融合视线与眨眼，不是立体场景深度重建。

1. 左右眼分别完成分割和三维眼球建模，各自减去正前方中心角，并按各自方向符号校正。
2. 两眼校正后的角度差不能超过 10°；通过后取均值，再除以默认 25° 范围并限制到 [-1, 1]。两眼相反方向不会被直接平均成直行。
3. 两路帧读取完成时间差必须小于 80 ms，处理后帧龄必须小于 250 ms；这是软件时间检查，不是硬件同步曝光。
4. 左右眼均睁开才确认睁眼，均闭合才确认闭眼；必须先确认睁眼才能接受闭眼。开闭不一致或 unknown 可沿用最近一致状态最多 100 ms，超过后输入无效。三维模型无效、方向冲突或帧过期会直接使输入无效，不经过此宽限。
5. 任一眼建模或中心无效，双眼控制均无效，不自动降级为单眼。闭眼时仅在几何模块允许的短时间内沿用此前稳定的眼球状态，不是在闭眼图像中重新估计视线。

## 9. 停止、直行与转向如何转换

检测层只发布 `[horizontal, closed, valid]`；“是否允许行驶”由下游控制状态机决定。看正中只是方向输入，不能单独解除暂停。

### 海龟控制器（`--ritnet`）

| 当前状态 | 触发条件 | 下一状态/动作 |
|---|---|---|
| 未启用 DISARMED | 900 ms 窗口内完成两次符合条件的眨眼 | ACTIVE，开始行驶 |
| ACTIVE | 持续闭眼达到约 650 ms | PAUSED，停车，保留会话 |
| ACTIVE | 无效输入、超过 400 ms 无消息、触墙 | PAUSED，停车 |
| PAUSED | 仅睁眼或仅看正中 | 保持停止 |
| PAUSED | 有效睁眼 → 闭眼 60～400 ms → 再有效睁眼 | ACTIVE，恢复行驶 |
| 任意状态 | `/eye_turtle/stop` 急停消息为 true | DISARMED，撤销会话，需要重新双眨眼 |
| ACTIVE | 横向输入小于 -0.25 / 大于 +0.25 | 向左/向右转向脉冲，持续约 1 秒，同时继续前进 |
| 转向脉冲中 | 1 秒到期 | 结束该次转向，通常回到直行；若已回中重新允许转向且又看向侧方，可立即触发新脉冲 |

转向重新触发前需要回到 `abs(horizontal) < 0.15`。因此转向不是“始终盯左就一直左转”，回中也不会提前取消已经开始的 1 秒转向脉冲。

恢复时并不要求看正中：单眨眼恢复的是 ACTIVE 行驶权限，当前如果仍看侧方，下一控制周期可以马上转向。要恢复直行，应看正中完成短眨眼。

实现细节：首次双眨眼计数要求每次闭合至少 60 ms 且小于长闭眼阈值 650 ms，并检查眨眼冷却（RITnet 启动器设为 120 ms）；暂停恢复的单眨眼才严格使用 60～400 ms。两者目前并非完全相同的判定范围。

### 轮椅默认模式（`--gazebo`，directional_intent）

停止后看正中，稳定约 250 ms，形成直行候选；随后完成两次 60～400 ms 短眨眼，两次完成之间不超过 450 ms，发送直行确认事件。仍需下游接收确认且满足控制/安全条件才能运动。仅睁眼、仅看正中、单眨眼都不能恢复。

看左/右同样先形成方向候选，再双眨眼确认；长闭眼约 650 ms 或输入失效会停车。该模式使用轮椅工作区的 `eye_shared_control/confirm.py` 和 `confirm_node.py`，并不使用海龟的 `Motion` 状态机。显式选择 `gaze_joystick` 时才使用另一套单眨眼暂停恢复逻辑。

主要代码：`tools/ritnet_tracker.py`（融合及发布）、`tools/gaze_3d.py:CenterCalibration.horizontal`（角度一致性）、`tools/dual_eye_tracker.py:BinocularState`（双眼开闭融合）、`src/eye_turtle_control/eye_turtle_control/controller.py`（海龟状态和转向）、`resume.py`（暂停恢复手势）。
