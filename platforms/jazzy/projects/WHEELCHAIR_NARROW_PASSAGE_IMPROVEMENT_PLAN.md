# 轮椅窄道与窄门通行改进方案

日期：2026-10-13  
性质：改进计划；已按本文实现可选的直通道/门洞首版，完整组合验收和实机能力测量尚未完成。实现范围与证据见 [实现说明](WHEELCHAIR_NARROW_PASSAGE_IMPLEMENTATION.md)。  
关联现状：[避障逻辑概述](WHEELCHAIR_OBSTACLE_AVOIDANCE_OVERVIEW.md)。

## 1. 目标与控制原则

解决当前轮椅在窄走廊中不能修正朝向、在门前或门内所有动作被拒绝、辅助一次后无法连续通行的问题。

继续保持“人用眼动等价于遥杆”的定位：用户决定启停和方向，系统限制危险动作，并协助对正通道。局部参考点只服务于当前用户意图，不产生脱离用户持续授权的导航任务。

- 保留 STOP、FORWARD、LEFT、RIGHT 四种固定档位动作。
- 不增加自动倒车、任意速度控制、默认前进转向组合或高频开停调速。
- 保留完整车体碰撞检查、实际 odom、制动过程预测和命令失效停车。
- 用户 STOP、输入失效或方向改变立即取消旧候选；实际运动按可实现的制动过程停止。
- 明确 LEFT/RIGHT 请求不能被自动替换为相反方向或前进。
- 保留 `stop_only` 对照模式，新增辅助行为应可单独配置和关闭。

本方案可以改善软件过度保守和规划不足，但不能保证通过物理上不可行的门洞。若最小可控转角、固定前进速度和制动距离本身不适合某种空间，应报告不可执行，不能通过缩短预测或删掉余量伪造可行性。

实施前必须复现并保存场景状态，不把所有停车都归因于几何。`ACTION_STALE`、地图/odom 超时和规划计算超时需要与几何拒绝分别处理。

## 3. 当前问题分析

### 3.1 多层膨胀使有效宽度达到约 0.886 m

当前仿真实体宽约 0.60 m，规划轮廓宽 0.70 m，另有：

```text
padding = margin + model_error + sampling_error
        = 0.06 + 0.025
          + (0.372 + hypot(0.55, 0.35) × 0.403) × 0.025 / 2
        ≈ 0.092934 m
```

完全对正时，理想平行墙之间的净宽须大于 `0.70 + 2 × padding ≈ 0.886 m`，尚未包含离线地图栅格化对门框的扩张。地图扩张量应对具体门洞测量，不假定总是固定减少某个宽度。

对长 1.00 m、宽 0.70 m 的矩形，朝向偏差 θ 时，在平行走廊里的横向占用为：

`W(θ) = 0.70 × |cos θ| + 1.00 × |sin θ| + 2 × padding`

| 偏角 | 所需净宽约值 |
|---|---:|
| 0° | 0.886 m |
| 3° | 0.937 m |
| 5° | 0.970 m |
| 10° | 1.049 m |
| 15° | 1.121 m |

此表是平行走廊的静态横向占用估算；有限厚度门洞、偏心位置和旋转扫掠仍须做完整几何检查。它解释了为何略微斜着进入窄道后动作很快被拒绝。

### 3.2 当前转向候选过粗

默认最小动作 0.30 s，加上 0.15 s 授权时间、0.10 s 通信与周期延迟，以及角制动，静止出发的转向预测约为 12°。

以无初始运动、无额外历史反应运动为条件，角加速度 0.8 rad/s²，0.45 s 后角速度约 0.36 rad/s，低于左右固定角速度上限；累计转角约为：

`0.5 × 0.8 × 0.45² + 0.36 × 0.10 + 0.36² / (2 × 0.7) ≈ 12.0°`

这不是每次实机转向的测量结果。运动中、观测陈旧或状态不同会产生其他包络。但它说明：只需几度修正时，当前默认候选仍可能因为更大的未来扫掠被拒绝。

### 3.3 辅助触发太晚，候选序列不足

当前直接前进安全就继续直行，直到前进不安全才尝试“停车→左/右转→停车→前进”。没有持续估计通道方向和居中误差，也没有主动在入口外对正。

当前候选不能完整表达“调整横向位置，然后恢复平行朝向”。带角度偏差进入狭窄区域后才尝试修正，可能已无转动空间。

### 3.4 保护间距同时用于恢复与初始判定，可能形成锁死

`Planner.tick()` 的 ready 条件要求当前位置 clearance 大于完整 padding；`Predictor.check()` 也会在初始位置不满足该条件时拒绝所有候选。

因此，处于完整保护间距以内但未实际接触时，可能无法重新授权，连潜在远离障碍的动作也无法进入评估。不能简单删除初始检查：需要先区分硬安全边界和舒适距离。

### 3.5 一次侧偏和两秒预算不适合连续居中

当前 `ASSIST_ALREADY_USED`、`ASSIST_TIME_LIMIT` 以及锁定的角度/横移参考，能限制自动接管，但不能有效描述“沿用户选择的走廊连续进行小幅对正”。

不能只把时间改成无限或每周期刷新参考；需要把权限约束改为明确的通道跟随范围，避免逐步变成自动选路。

## 4. 修改一：分离真实轮廓、硬安全余量和舒适距离

### 实施要求

1. 核对 Gazebo collision 几何、base frame 原点、实体外廓和规划轮廓，确认 0.60 m 与 0.70 m 的差异来源。真实突出部分必须保留；仿真尺寸不能直接视作实机轮廓。
2. 为每项误差建立预算表：轮廓建模、定位、地图量化、控制跟踪、轨迹采样和时间误差。记录来源、覆盖范围和是否与其他项重复。
3. 将舒适距离从硬碰撞禁止条件中分离，改为轨迹评分偏好。所有必须覆盖的不确定性继续留在硬约束中。
4. 硬约束仍检查完整扫掠及停车包络；不能仅把速度或距离变化变成软惩罚。
5. 不因识别为窄门就临时压低未经验证的硬安全余量。

### 地图修正

- 测量原始几何门宽与生成地图门宽的差异，检查栅格保守扩张和矩形合并是否填掉凹口或门边空间。
- 优先保留准确静态多边形；必要时提高门洞附近地图分辨率，并记录误差界。
- 不能通过删除门框点、裁掉真实突出物或把未知区域当自由空间解决过门。
- 当前基于已知仿真地图，可先用该地图验证规划。实时雷达障碍融合是另外的工作，不能宣称已解决动态感知。

### 验收

在真实碰撞几何相同的条件下，比较修改前后净宽、硬安全宽度和可行姿态。只把已证明属于重复膨胀或软偏好的部分移除。

## 5. 修改二：支持可执行的微小转向

保持固定角速度档位，改变动作持续时间/目标转角，通过实际 odom 提前制动。

- 先在仿真中测量最小可靠动作、转动启动延迟、释放延迟、转动停止角和误差范围；实机接入时必须重测。
- 搜索多个可执行的转向幅度。2°、4°、6°等仅可作为实验候选，不作为硬件已具备的能力承诺。
- 预测器与执行器使用同一套动作能力参数，不允许预测器检查短动作而执行器仍保持长动作。
- 区分“动作续期/失联后的最坏持续时间”和“计划主动停车时间”。主动停车可以早于授权过期，但安全包络仍要覆盖该链路实际承诺的最坏停车时延。
- 不可忽略执行器停稳等待、启动延迟、通信队列、规划超时和制动尾段。
- 不使用高频启停产生平均低速；持续相同动作只续期。

若底层只能可靠执行较大转角，直接将小转角候选标为不可执行；在门外提前对正，或报告该姿态下无法修正。

## 6. 修改三：提前估计通道并做居中辅助

增加可关闭的 `corridor_assist` 行为，名称可按工程规范调整。

### 通道表示

根据已知地图中的局部自由空间或后续传感器地图，得到左右边界、通道方向、可行通行带、可信范围和最近出口/分叉。中心线是优化参考，不代表沿中心一定安全。

计算横向误差、朝向误差和预测安全间距。在直接前进仍安全时也评估是否需要提前纠正，避免等到车角贴墙才介入。

### 规划行为

- 在入口外优先完成大的对正调整。
- 在通道内搜索保持前进及必要的微小转向；每个候选仍执行完整硬安全检查。
- 评分加入朝向误差、横向误差、前进进度、舒适间距和切换次数。
- 设置偏差滞回和最小有意义改善量，避免左右反复修正；STOP 不受滞回延迟。
- 搜索适当的多段序列，允许表达“转向→前进→转回”，但只执行当前短段。
- 不能因为某序列终点居中而忽略中途车体扫掠。

### 人机权限边界

- 只在用户持续授权 FORWARD 且存在清晰通道时辅助。
- 首个版本限定直走廊/门洞附近，不能自动把 90°弯道或分叉当成继续前进。
- 分叉、通道方向变化超出权限、识别不确定或无安全动作时停车，由人选择方向。
- 通道对象和参考方向需要稳定跟踪，不能每周期重建以绕过累计偏转限制。
- 在一次已确认的通道内允许多次有限微调；单次修正、整体方向偏离及横向范围仍有限制。
- 用户明确 LEFT/RIGHT 时取消辅助，执行安全的人工方向请求；STOP 或失效时丢弃所有后续段。

## 7. 修改四：增加门前对正与短距离过门辅助

建议状态：`APPROACH → ALIGN → TRAVERSE → EXIT`，另有 `BLOCKED/CANCELLED`。这些状态均受用户持续授权约束。

1. 检查门洞净宽、厚度、两侧突出物、入口调整空间、出口空间和可停区域。
2. 在门外建立局部对正参考位姿，规划必要的横向位置与朝向调整。
3. 进入门洞前，验证完整穿越运动及可中断停车的安全性；检查从当前姿态到目标姿态的连续路径，而非只检查目标点。
4. 穿门时尽量保持已对正的朝向，避免门框之间才做大幅旋转。
5. 出门后退出该局部辅助过程；没有用户持续 FORWARD 授权时不继续行驶。

参考位姿不是自动导航任务，不能在用户 STOP 后继续“完成过门”。若调整需要后退、前进转向组合或超过授权范围，明确停车提示，不能偷偷加入新动作。

## 8. 修改五：区分软间距、阻挡和故障恢复

| 情况 | 建议行为 |
|---|---|
| 进入舒适间距，但满足全部硬安全约束 | 可评估安全动作，优先改善间距，不因软偏好锁死 |
| 请求动作不安全，但当前停车安全 | 拒绝该动作；按现有确认流程允许新的人工方向请求 |
| 当前已违反硬安全边界 | 保持停车并给出明确原因，不自动放宽阈值 |
| 传感器、时钟、执行器等故障 | 保留故障锁定和重新授权流程 |

对于硬边界内的恢复，本阶段不默认实现自动脱困。若以后新增专门恢复模式，必须有显式用户授权、真实几何无接触的验证、完整扫掠检查及明确误差假设。仅“车体中心离墙更远”不足以证明恢复安全。

修改 ready 判定时，应明确它是在检查硬安全几何，而不是舒适间距。不得让连续旧 FORWARD 消息自动解除阻挡或故障。

## 9. 首先补齐诊断和可视化

每次拒绝至少记录：

- 当前意图、请求动作、实际动作、当前模式、会话/时间戳。
- 当前实际姿态/速度、源数据年龄、compute_ms、执行器拒绝原因。
- 本次候选的持续时间、目标转角和预计停止位置。
- 最早失败的预测时刻、车体姿态、障碍 ID/边界及最近点。
- 原始几何间距、硬余量各分量、舒适距离和最终判定。
- 区分初始硬边界违规、未来碰撞、未知区域、辅助权限不足和动作不可执行。
- 通道横向/朝向误差、门洞测量宽度、地图宽度以及辅助参考。

在 RViz 或现有显示中叠加：真实轮廓、硬安全轮廓、舒适范围、候选扫掠、预测停止位姿、首次违规点和局部通行带。诊断须标记对应决策序号，不让旧候选看起来像当前结果。

## 10. 实施顺序与代码落点

| 优先级 | 工作 | 主要位置 |
|---|---|---|
| P0 | 复现卡点、保存 odom/地图/意图、补充首次失败诊断 | nodes.py、planner.py、实验脚本 |
| P1 | 几何核对与误差预算，分离软硬间距 | control.yaml、geometry.py、地图生成工具 |
| P2 | 可实现的转向幅度搜索与停车控制 | planner.py、executor.py、参数与协议（必要时） |
| P3 | 提前对正、通道居中、多段动作搜索 | 新局部通道模块、planner.py |
| P4 | 门前调整与过门状态机 | 新门洞辅助模块、planner.py |
| P5 | 恢复规则、权限和性能回归 | nodes.py、planner.py、集成测试 |

软硬间距修改涉及恢复判定时须同步完成相应回归，不能等到 P5 才检查。保持旧模式可运行；新功能逐阶段通过测试后再启用，不一次性替换全部链路。

控制循环目标周期为 50 ms。扩展搜索必须测量最坏耗时和负载下的超时行为；超预算时安全停车，不能续发未经新状态验证的运动命令。不得仅调大 TTL 掩盖计算超时。

## 11. 仿真验收矩阵

### 几何与通行能力

- 平行走廊：按修正后的硬可行宽度设置上下两侧的宽度样本，另外覆盖 0.80、0.90、1.00、1.10 m 等场景；这些数值是测试点，不是承诺可通过的宽度。
- 初始偏角：0°、±3°、±5°、±10°；初始位置包括居中及左右偏置。
- 门洞：不同宽度、墙厚、门框突出、出口空间和接近角度。
- 转向：贴墙时安全的小角度修正、不安全的大角度旋转、物理上确实无法转动。
- 区分入口外可调整与门内已无调整空间的情况；后者允许正确拒绝。

### 控制与权限

- 用户持续 FORWARD 时可多次有限居中，不因一次辅助额度用尽无故终止。
- STOP 在所有阶段取消后续动作；改方向不继续旧门洞/走廊计划。
- 分叉及超过方向权限时不自动选路。
- 信号失效、执行器退出、动作超时和重启后不会恢复旧运动。
- 附近只违反软间距时不永久锁死；硬边界违规不能被软评分放行。

### 可执行性与性能

- 每个候选转角都在执行器支持范围内，预测停止包络覆盖实际运动误差。
- 延迟、丢帧、规划高负载和不同制动参数下验证停车行为。
- 比较原版本、stop_only、新通道辅助和门洞辅助。
- 记录碰撞/接触次数、最小硬间距、完成率、耗时、用户操作次数、动作切换次数、拒绝原因及计算延迟分布。

对声称能够安全通行的测试，要求无接触且硬安全约束持续满足；“停着所以零碰撞”不能视为通行成功。对不可行案例要求正确停车和可解释原因，而不是强行提高通过率。

## 12. 交付与非目标

实施 agent 应交付：问题复现记录、误差预算、修改代码及配置、可执行启动命令、参数说明、测试结果和前后对比。更新现状概述时，只写已实现并验证的行为，不能把本方案直接改写成完成报告。

本轮不自动连接真实轮椅、不修改 ESP32 固件、不宣称解决实时点云或动态行人感知、不引入目的地导航。任何算法调整都不得通过缩小真实车体、忽略制动、伪造反馈或单独放宽时效限制来取得通过结果。
