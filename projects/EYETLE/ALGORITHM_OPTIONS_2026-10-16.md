# GitHub 算法筛选与融合建议

检索日期：2026-10-16。现有设备为固定安装的两台近眼摄像头，需求是左/中/右与眨眼控制，而非精确屏幕注视点。单眼、双眼均可考虑；优先减少反复建模和用户操作。

## 已执行

默认海龟入口及 `--teyed` 显式使用 TEyeD 方向 + RITnet 睁闭眼。Itoh 仅保留试验入口。脚本语法和检测器参数解析已检查，没有启动运动程序，也没有把未验证的新算法切入控制。

```bash
./start_eye_turtle.sh --teyed 2>&1 | tee model-results/teyed-ritnet-live.log
```

## 候选及取舍

### 1. PuRe / PuReST：优先作为二维瞳孔备选

[PyPupilEXT](https://github.com/openPupil/PyPupilEXT) 集成 PuRe、PuReST、ElSe 等方法，提供统一的瞳孔椭圆与轮廓置信度接口。它们是检测/跟踪算法，不是免标定的视线控制器。文档中的 stereo 主要用于物理瞳孔尺寸三角测量，不等同于我们左右眼分别取景的双眼融合。

我的建议：在 RITnet 已定位的眼区内运行 PuRe/PuReST，比较两个椭圆的中心和轮廓质量。无需在线三维眼球拟合；从二维位置到左右方向的映射由本项目完成。固定相机条件下，首次简短左/中/右采集并保存是可评估的方案，后续尝试仅做中心确认，不能预先承诺换人/重戴仍准确。

部署：已有 C++/Python 接口，但列出的 Linux wheel 是 x86_64，Jetson aarch64 需要确认或编译。部分集成算法限非商业研究用途，采用具体实现时需对应许可。

### 2. EllSeg：优先评估侧视遮挡时的特征检测

[EllSeg](https://github.com/RSKothari/EllSeg) 针对瞳孔/虹膜完整椭圆建模，提供预训练模型说明和视频评估脚本，适合对照当前侧视时丢瞳孔的问题。它本身不输出已标定的控制方向，也不提供已验证的闭眼控制流程。README 推荐另一个维护仓库，正式接入前应确认权重可获取、依赖及 TensorRT 转换。

我的建议：比较 pupil/iris 中心、椭圆归一化位置等特征对左中右的区分度；将“完整椭圆补全”与“实际眼睑闭合”分开，不能把闭眼时仍预测出的椭圆当可靠注视。

### 3. EyeTrackVR：借鉴双眼工程流程，不视作免标定替换

[EyeTrackVR](https://github.com/EyeTrackVR/EyeTrackVR) 面向近眼双摄像头。[官方操作指南](https://docs.eyetrackvr.dev/software_guide/eyetrackvr_app_guide) 包含眼区裁剪、旋转、阈值设置、看各方向极限及中心确认。因此不宜声称装上就更省标定；可借鉴它的独立眼配置和用户反馈流程。

### 4. 3DeepVOG：研究备选，当前不优先

[3DeepVOG](https://github.com/DSGZ-MotionLab/3DeepVOG) 支持单眼瞳孔/虹膜分割和几何视线估计，单独标定视频是可选项，但仍包含眼球拟合，并明确建议已知相机内参，提及 pye3d 折射修正。它不是完全跳过建模的路线。官方测试平台与我们不同，仓库中的速度/误差不能用于承诺 Jetson 的表现。

### 5. Baballonia：不符合当前“简短标定”优先级

[Baballonia](https://github.com/Project-Babble/Baballonia) 提供 XR 眼/脸追踪。[官方标定说明](https://docs.babble.diy/blog/eballs) 描述了注视固定目标并转头采集、约 20 秒闭眼采集，以及约 5～10 分钟个性化训练。按该文档流程，当前不优先采用；它的产品形态也不能直接等同于 Jetson 上可加载的独立眼动权重。

## 建议的下一套实验（尚未实现）

1. 保留 RITnet 眼区定位/分割，加入 PuRe/PuReST 作为同一只眼的独立二维检测候选。
2. 各方法先映射到同一个左/中/右尺度，再评估融合；不能直接平均 TEyeD 的向量分量和瞳孔像素位置。
3. 简短自动引导左、中、右采集，校正每只眼、每种特征的方向符号与幅度，保存配置。看正前方的单点采集只能确定偏置，不能单独辨识增益和左右反转。
4. 在同一批带动作标签的视频上比较：当前 TEyeD+RITnet、二维 RITnet、PuReST、EllSeg，以及验证后选择的融合。记录每个方向的混淆、眨眼事件检出/误检、遮挡误启动、延迟和暂停原因。
5. 根据验证结果决定用单眼、双眼或质量加权；不为了掩盖双眼冲突在行驶中无提示切换单眼。
6. 眨眼要独立修复事件时间匹配。此前日志中的有效闭合只有约 52 ms 或重新睁开前输入无效，会导致计数丢失；更换方向模型本身不会修好这两个问题。未知状态不直接当闭眼。

这里的融合与标定时长是工程方案，不是上述项目已经验证的能力。暂不宣称任何候选在本机更准；先用离线、有动作标签的共同样本筛选，再接小乌龟。
