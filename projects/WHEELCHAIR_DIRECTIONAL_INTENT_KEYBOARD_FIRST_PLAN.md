# 方向意图驱动的共享驾驶：键盘先行、眼动后接实施方案

日期：2026-10-14  
状态：供实施 agent 执行的方案，尚未实现或验证。

## 1. 用户要求与优先级

用户仅能使用眼睛，不能依赖频繁弹窗、语音问答或逐次确认。系统自动解释方向意图，决定在哪里转、什么时候转及怎样避障。用户用停止或新方向意图纠正系统。

本轮先用键盘模拟意图，验证规划行为；之后接入眼动，保持相同意图接口和下层行为。假设仿真感知无误检、几何与 odom 准确，集中研究意图保持和通路规划。这个假设不等于执行无延迟、能瞬间停车，仍需建模固定档位、惯性、通信与制动。

本方案覆盖此前文档中冲突的交互规则：

- **取消每次方向操作的候选提示和双眨眼确认。**
- **回正不取消正在执行的转入意图，也不重新生成前方目标。**
- **一次稳定侧视只生成一个方向事件，不持续旋转或不断重复选入口。**
- 仅启动/停止后的重新启动使用明确启动动作；内部停车恢复握手由软件完成，不要求用户额外操作。
- 用户界面可有被动状态显示；详细诊断只供开发者，不能阻塞行驶或要求用户回答。

本文件优先于 [上一版确认式意图方案](WHEELCHAIR_INTENT_SHARED_CONTROL_IMPLEMENTATION_PLAN.md) 中“候选—逐次确认—执行”的规定。可复用其中的消息去重、健康心跳和取消机制。

## 2. 目标行为

典型场景：轮椅在走廊中，前方左侧有入口，人提前给出左侧意图。

```text
一次左侧意图
  → 在有限范围内选择前方最近的可达左侧入口
  → 锁定入口身份
  → 沿走廊接近适当位置
  → 对正并转入
  → 整车通过入口后清除本次左侧意图
  → 沿新方向继续安全行驶
```

禁止把“左侧意图”实现为当前位置正左侧的目标点；禁止等到前方直行碰撞才开始考虑入口。已选择入口时，轮椅暂时直行属于执行左侧意图的一部分。

完美环境感知不能确定人的真实意图。第一版采用明确、可测试的默认规则，不声称能辨认用户究竟想进入哪间房。

## 3. 输入语义和键盘映射

新增独立模式，例如 `control_mode:=directional_intent`。旧遥杆模式保留作对照，不能在旧模式中静默改变按键含义。

| 按键 | 意图事件 | 行为 |
|---|---|---|
| W | START_OR_CONTINUE | 停止时启动；运行中保持当前意图和路线，不取消侧向任务或刷新预算 |
| A | PREFER_LEFT | 运行时提交一次左侧偏好，自动选路；不是直接下发 LEFT 动作 |
| D | PREFER_RIGHT | 同上，右侧 |
| C | CANCEL_PREFERENCE | 开发测试用：取消侧向任务，安全停车后重新建立当前方向巡航；眼动首版不映射该操作 |
| 空格 / S | STOP | 取消全部任务、偏好和待执行段，并停车 |
| X / Ctrl+C | EXIT | 发布 STOP 并退出，执行端看门狗作为后备 |

停止状态 A/D 不启动车辆；先 W 启动。这样键盘与“眼动启动授权后才能转向”的语义一致。

连续重复的同方向按键不重新选入口、不重置计时或扩大搜索范围。终端按键自动重复不应造成多个运动任务：同方向已有活动/待处理意图时视作幂等；方向事件完成后，设置输入释放/静默再触发机制。普通终端无 key-up，建议使用明确配置的无输入间隔去重，记录其限制；不能假装已检测到按键释放。

相反方向新事件替换旧意图：取消旧计划，先完成必要停车，在当前可行空间重新选择，不瞬间反向、不继续旧转入序列。

STOP 后必须有新的 W 才能启动；收到旧事件、心跳、重复状态或传感器恢复都不能启动。

## 4. 行为决策规则

### 4.1 无侧向意图：巡航

- 清晰走廊内沿当前通道居中前进；开阔区域保持本次锁定朝向。
- 路口存在唯一明确直行延续时可继续直行。
- 死胡同、没有唯一延续的分叉、无法在授权方向内继续时停车，不自行任选左右。
- 不因地图中出现一个侧门就主动进入。

### 4.2 走廊中的左/右意图

- 搜索当前行进方向前方、对应侧、有限距离范围内的入口。
- 入口至少满足几何可通行、转入轨迹可执行、入口内有足够已知安全空间。
- 按沿当前通道的前向距离选择最近的可达入口。距离相近时采用稳定的几何 ID 排序规则，不每帧随机换目标。
- 已经过且需要倒车的入口不选；后退不在本轮动作集合内。
- 找到后锁定入口 ID、所在侧、几何范围和参考方向。每帧重规划不能换成另一扇门。
- 目标在锁定后变得不可执行时停车，不悄悄换下一个入口。

### 4.3 暂未找到入口

- 保持沿当前安全路线前进，短期保留侧向偏好。
- 在有限搜索时间和前进路程内持续检查新进入局部范围的入口。
- 预算耗尽后清除偏好，继续原本安全的巡航；记录开发者状态，不向用户提出确认问题。
- 偏好过期不代表强制前进：没有安全巡航动作仍停车。

### 4.4 开阔区域

- 没有走廊/入口约束时，侧向事件对应一次有限朝向偏置，再沿新方向前进。
- 建议从相对当前参考方向 ±20° 的仿真初值开始；实际目标须满足运动可达和停车条件。
- 不选择绕到背后的目标，不无限累计侧向角度；一次事件完成后必须有新事件才能再次偏转。
- 当前空间分类、选中目标及解释一旦确定应稳定保持，不能在“开阔左偏”和“进入左门”之间逐帧跳变。

### 4.5 转入完成后

- 整车通过门洞，并完成对正后，消耗这次侧向事件。
- 建立新通道或新朝向巡航参考，不沿用旧走廊的侧向偏好。
- 入口后没有足够安全继续空间、无法确定前进方向或即将遇到新的选择点时停车。
- 允许沿新通道继续，但不自动执行第二次分支选择。

## 5. 偏好和任务范围参数

初始建议仅用于仿真实验，统一放入新配置文件，不散落硬编码：

| 参数 | 仿真初值 | 语义 |
|---|---:|---|
| intent_search_distance | 3.0 m | 从事件产生点起沿实际巡航累计的最大入口搜索路程 |
| intent_search_timeout | 8.0 s | 无入口时的偏好保留上限 |
| entry_lookahead | 3.0 m | 在当前局部环境中可考虑的前向入口范围 |
| open_area_heading_bias | 20° | 开阔区域单次方向偏置 |
| maneuver_timeout | 20 s | 选定入口后的任务执行上限，防止长期卡住 |
| progress_timeout | 3 s | 排除合理停车转换阶段后，持续无有效进度的检查初值 |

搜索预算从事件产生起算，心跳、重复事件、重规划和临时停顿不能清零。入口锁定后结束搜索阶段，转入独立任务预算；入口丢失/任务失败不能自动重新开始搜索。

不要用上一方案“每 10 秒/3 米必须重新确认”的规则打断正常巡航。本轮无须周期确认，但巡航需要连续健康心跳、真实执行反馈和每周期安全检查；失效必须停车。

## 6. 分层架构

```text
键盘事件（本轮） / 眼动事件（后续）
          ↓                         ↓ 输入健康心跳
统一方向意图管理器
          ↓
环境通路解释：走廊、开口、可达入口
          ↓
任务状态机：巡航 / 搜索 / 接近 / 转入 / 穿门 / 退出
          ↓
局部目标位姿 + 可执行运动基元规划
          ↓
完整轮廓、延迟和制动安全检查
          ↓
STOP / FORWARD / LEFT / RIGHT 执行器
```

首版可使用准确仿真地图提取入口，但不得写死办公室门的位置或具体按键触发坐标。入口在地图中有明确几何身份；无法识别房间语义时统一称为入口/开口。

## 7. 任务状态机与局部规划

建议状态：

`STOPPED → CRUISE → SEEK_ENTRY → APPROACH_ENTRY → ALIGN_ENTRY → TRAVERSE → EXIT → CRUISE`

也允许 SEEK_ENTRY 过期回到 CRUISE，任意状态 STOP/故障进入 STOPPED/BLOCKED。开阔区域使用独立的有限朝向偏置子任务。

### 局部目标生成

- 目标位姿保存在 odom/map 一致坐标系中，不每周期按当前车头重新生成。
- 根据入口宽度、墙厚、转入扫掠和底盘能力生成接近、对正、穿门、出口参考位姿。
- 门中心不是充分条件；整条轨迹和任何可能中断后的停车包络都须检查。
- 原地旋转的空间不够时，可以在入口外提前调整，但不能加入未支持的倒车或横移。
- 小范围局部绕行不能变成自动绕整栋建筑，限制在当前目标及其局部可达空间内。

### 运动连续性

- 复用现有固定档位动作模型，不把普通连续速度规划结果简单量化为按键。
- 只搜索底盘实际支持的动作及持续时间，包括必须的停车转换。
- 规划评分包含路径进度、间距、旋转/切换次数和新旧轨迹偏离；有安全且有效的旧轨迹时，不为微小评分改善频繁换计划。
- 中间参考点不是必须停下的终点，同方向段应连续执行；需要旋转的段仍按底盘约束停稳后切换。
- 目标容差要与实际制动和最小可控动作一致，防止来回修正。
- 精确 odom 不代表零制动距离。检查真实速度、执行延迟、动作 TTL 和最终停止过程。

## 8. 接口与消息职责

不要直接复用旧 ControlIntent.command 的 LEFT 表示“持续转动”。新增方向事件协议，或通过明确的新适配层区分事件与底层动作。

### DirectionEvent

建议字段：header、source_session_id、event_id、kind（START_OR_CONTINUE/PREFER_LEFT/PREFER_RIGHT/CANCEL_PREFERENCE/STOP）、ttl_ms。

- event_id 用于去重，重发同一事件只返回同一 ACK，不重复执行。
- 启动和方向事件必须新鲜；过期、乱序、旧 session 不能启动动作。
- STOP 走优先取消路径，不需要候选，也不等待规划搜索完成。
- ACK 仅用于软件一致性和日志，不要求用户确认 ACK。

### InputHealth

独立发布源 session、序号、时间、valid、ttl。心跳证明输入链路仍健康，不产生方向事件、不延长偏好或任务预算。

### NavigationIntentStatus

记录活动 event_id、task_id、偏好方向、锁定入口 ID、任务阶段、剩余预算、当前局部目标、实际动作、原因。状态供调试/被动显示，不作为用户必须回应的提示。

### 安全与恢复

- 选择 keyboard 或 eye 单一来源，启动时配置；不自动切换来源。
- 保留动作层短 TTL、独立底盘看门狗和最终安全检查。
- 软件自动完成原有 disabled STOP→ready 内部握手。正常启动按 W 即可，健康不满足则保持停止；不要求再按 R 才能表达恢复意图。
- 故障清除不恢复旧任务，需要健康恢复之后的新 W（眼动模式对应新启动手势）。故障期间的启动请求不永久排队等待执行。
- 任一进程重启、时钟异常或输入会话切换，清除旧偏好和旧动作授权，默认停止。
- 运动消息采用 volatile、小队列；不能用历史持久消息恢复运动。

## 9. 键盘端具体修改

主要文件：`wheelchair_shared_ws/src/wheelchair_control/wheelchair_control/inputs.py` 及启动脚本。

当前 Keyboard.key() 将 W/A/D 保存为持续 FORWARD/LEFT/RIGHT，并周期发布。新模式必须改成：

1. 按键边沿/去重后发一次方向事件，另一个定时器发健康心跳。
2. 不再周期生成新的左/右事件；W 心跳不能刷新入口选择。
3. A/D 不直接到达底盘动作话题。
4. STOP 清空源端待发送事件，并经过独立停车入口取消下层任务。
5. 保留旧键盘节点/模式，提供新模式帮助文本，避免测试者误以为 A 是立即原地左转。
6. 详细状态通过独立 status/trace 工具查看，不在主交互循环反复打印“请确认/按 R”。

要求提供一键仿真、键盘输入和状态查看命令，具体命令随实现写入 README；不要只交付架构而无法运行。

## 10. 后续眼动接入：必须修改的位置

主要文件：

- `wheelchair_shared_ws/src/eye_shared_control/eye_shared_control/core.py`
- 同目录 `node.py`、`resume.py`
- `wheelchair_shared_ws/src/eye_shared_control/config/eye.yaml`
- 该包的状态机、合成输入和接口测试。

### 10.1 停止输出逐帧方向控制

删除新模式中“候选 dwell 满足后 command=LEFT/RIGHT/FORWARD”的直接动作映射。改为两套独立状态：

- 运动会话：STOPPED / ACTIVE / BLOCKED / INVALID。
- 方向事件检测：READY / LEFT_HELD / RIGHT_HELD / WAIT_NEUTRAL。

### 10.2 稳定侧视自动提交一次事件

- ACTIVE 中看左/右稳定达到 dwell 就发布 PREFER_LEFT/PREFER_RIGHT，不要求双眨眼确认。
- 建议先复用 dwell=250 ms、enter=0.25、leave=0.15 作实验初值。
- 持续同侧注视不得重复提交，即使入口任务已经完成也不能再次提交。
- 同侧再次触发需先回正并稳定一段时间，再重新看向该侧。
- 相反侧稳定注视可以生成替换事件，不必先回正；必须有滞回和稳定窗口，避免左右抖动连续换任务。
- 回正只重新准备下一次触发，不发 START、不取消目标、不改变巡航参考。

### 10.3 启停与健康

- 停止状态用一次明确的启动手势进入 ACTIVE；建议保留双眨眼作为启动/停止后的重新启动，而非方向确认。
- 首版新模式禁用单眨眼恢复旧任务，避免自然眨眼误恢复；旧 ResumeGesture 仅保留在旧模式。
- 长闭眼沿用约 650 ms 初值，触发 STOP 并清空活动意图；停止不经过方向 dwell。
- 健康扫视和正常短眨眼不取消已提交任务；源 invalid、超时或下层故障必须停车。
- 停止/失效时重置方向触发器；恢复后没有新启动手势不得移动。
- 正常眨眼期间保持当前事件检测状态或有限冻结；不得用冻结掩盖真实检测失效。

### 10.4 时间与反馈

- 分开候选识别、事件提交和源健康心跳。定时发健康消息不能掩盖旧帧。
- 能提供源采集时间和序号时优先使用；旧 Float32MultiArray 适配明确只能按接收时间判断。
- 保留开发用状态：检测方向、是否已触发、下次是否需要回正；用户不需要读取并回应。
- 测量自然观察、持续看人、正常双眨眼等引起的误事件。完美雷达/odom 不代表眼动意图判断完美。

## 11. 实施顺序与职责

### 阶段一：接口与键盘意图管理

实现 DirectionEvent、健康心跳、事件去重、偏好状态和启动/停止。用假通路输入做单元测试，再接真实仿真地图。

### 阶段二：入口识别与锁定

从准确地图提取局部走廊与侧向开口，实现最近可达入口选择、搜索预算、目标身份保持。至少测试不同位置和宽度的入口，不能仅针对一个办公室位置通过。

### 阶段三：转入轨迹及连续巡航

复用已有 passage、planner、executor，实现接近、对正、穿门、退出和新方向巡航。保留微转向/完整碰撞检查，不能因新增目标层而退化为任意速度命令。

### 阶段四：键盘集成验收

先完成下面场景和回归，再接真实眼动。记录用户主观连续性以及动作切换、停顿、通过率，不能只看无碰撞。

### 阶段五：眼动适配

按第 10 节修改眼动包，只替换事件来源。相同事件序列应产生相同规划行为；键盘和眼动不能维护两套不同的入口选择算法。

如果分配多个 agent：规划/任务 agent 负责共享消息、意图管理和入口规划；输入 agent 负责键盘/眼动适配；接口先对齐后独立开发。本文不表示已经启动 agent。

## 12. 必须通过的键盘场景

| 场景 | 操作与预期 |
|---|---|
| 提前左转 | 到门前仍有距离时按 A，先沿走廊接近再转入，不能朝墙左转 |
| 入口附近左转 | 按 A 后规划完整转入，旋转空间不足则正确拒绝 |
| 两个左侧入口 | 选择前方最近可达入口，锁定后不跳到下一扇 |
| 最近入口不可达 | 锁定前可跳过已判定不可达入口；锁定后失败则停车，不自动换门 |
| 没有入口 | 偏好在预算内等待，过期清除，不在很久后突然转弯 |
| 入口在身后 | 不倒车，不选择需要回退的入口 |
| 开阔区域 | 一次 A 只做一次有限左偏，之后沿新方向继续 |
| 重复 A | 不重置任务、搜索距离或计时，不重复左转 |
| A 后 D | 取消旧侧向任务，安全停稳/切换后执行新意图 |
| 转入期间 W | 保持当前转入，不被 W 重置成旧走廊直行 |
| 任意阶段 STOP | 清除任务和偏好；松开/恢复消息不能继续 |
| 过门后继续 | 清除已消耗的侧向偏好，沿新通路走，不自动再转一次 |
| 分叉无新意图 | 唯一直行则保持；无唯一延续则停车，不随机选边 |
| 节点退出/超时 | 任务、规划、输入或执行器分别中断时最终失效停车 |

眼动阶段追加：短扫视无事件、稳定侧视一次事件、持续侧视不连发、回正只重置触发、反向注视可替换、单眨眼不启动、启动/停止正确、无效恢复不自动走。

## 13. 诊断、验收指标与交付

每次记录输入事件 ID、任务 ID、解释类型、锁定入口 ID、状态转移、参考位姿、动作、compute_ms、实际轨迹、停止原因与安全间距。

比较旧遥杆/局部给点与新方向意图模式：入口选择是否符合固定规则、通过率、接触次数、最低间距、完成时间、动作切换和停车次数、需要的人为操作次数。

安全候选要持续满足完整硬安全约束；困难或不可达场景允许正确停车。固定档位只能直行和原地旋转时，仍会有必要的停—转—走，不能宣称位控能消除这一物理限制。

交付代码、参数文件、键盘运行命令、测试脚本及结果、眼动改造清单和更新后的现状文档。眼动尚未接入时明确标注未完成，不把本方案写成实现报告。

不修改真实硬件、不引入需要用户不断确认的流程、不通过删掉制动或安全余量提高通过率、不把开发诊断变成用户必须完成的操作。
