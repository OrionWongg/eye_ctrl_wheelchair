# 原地转向受阻后的前方位置调整（试验方案）

2026-10-16，在已恢复的大厅转向版本上增加一个限定的失败分支。直接原地转向能执行时仍按原逻辑完成，不先平移，不恢复此前撤回的盲区掩码、全局提前防卡或通用脱困机制。

## 行为

- 仅在活动的原地转向、掉头或开阔区方向调整因几何空间不足或持续无进展而失败时启动；普通巡航、入门路线及输入/传感器/时钟故障不触发该搜索。
- 先 STOP 并确认执行器停稳，再沿停止时朝向检查前方 20、40、60 cm 三个候选。目标朝向保留原转向请求，不重新叠加角度。
- 复用 `/wheelchair/compute_discrete_path`，要求完整的“直线前进→停止→原地转向”路径，`allow_detour=false`。只接收一个前进段加一个转向段，拒绝倒车、侧移和绕行路径。
- 每个候选先让规划器验证停车位置容差较近的一侧，再验证候选中心的完整组合。搜索期间不运动；第一个通过的组合交给现有 `PathFollower` 执行。
- 执行前进和旋转时继续检查完整车体及停车轨迹。前进接近位移上限时，必要时先停车再继续剩余的短前进，不降低既有固定速度。
- 一次任务只执行一个选中的组合。选中后遇到新障碍、无进展、越界或超时，就停止并报告需要协助，不再执行第二个组合。全部候选不可达时也保持停车。
- 停车 A/D/U 完成后保持停车；原本行驶中的方向调整完成后保留原继续巡航语义。STOP、新方向替换和输入失联均取消旧搜索/动作，迟到的路径回复不能重新启动旧任务。

## 参数

`src/wheelchair_control/config/directional.yaml`：

```yaml
turn_adjust_distance: 0.60
turn_adjust_attempts: 3
turn_adjust_timeout: 20.0
```

候选距离均匀分布在前方范围内。候选中心最多前移 0.60 m；含现有 0.06 m 位置容差的实际位移上限为 0.66 m，预测也检查命令租约、传输和完整停车后的位移。原任务的转向/掉头总时间预算仍有效，不能被这个分支延长。

此处没有修改车体轮廓、margin、model_error、速度、动作租约、计算限时，也没有增加普通路线的整段可观测性预检。

## 提示与试用

键盘终端会报告正在搜索、已找到组合；无解或组合执行失败时显示：

> 已停车：没有可安全完成的前进＋转向组合，需要协助。

状态话题对应 `TURN_ADJUST_*` 阶段，失败原因为 `TURN_ADJUST_HELP_REQUIRED:...`。不新增确认键。

重启仿真和键盘进程后生效。原办公室入口不变：

```bash
~/wheelchair_shared_ws/scripts/run_direction_sim.sh scene:=clearpath_office gui:=true
~/wheelchair_shared_ws/scripts/direction_keyboard.sh
```

上述两条命令分别在两个终端执行。

为了观察这个失败分支，增加了独立的仿真场景，不修改办公室模型或车辆传感器：

```bash
~/wheelchair_shared_ws/scripts/run_direction_sim.sh scene:=turn_adjust_bay gui:=true
```

在该场景停车按 A/D/U，当前位置的短侧墙妨碍原地转向，前方有更大的空间。`scene:=turn_adjust_blocked` 在前方再加障碍，用于验证无安全组合时不运动并提示协助。

本方案沿用现有完整仿真障碍地图和安全控制器；验证结果仅针对仿真，不代表已完成实车硬件验收。

## 最终验证

完整回归 **363 passed**，控制与仿真包构建成功。九项实际仿真/键盘验收通过：组合左转、组合右转、组合掉头、无安全组合保持停车、调整途中 STOP、原办公室停车左转/右转/掉头，以及真实键盘终端的协助提示。碰撞 0，无活动任务的计算超时或 ACTION_STALE，最大控制计算耗时 45.39 ms。

在测试窄处，左/右转前移约 36.7 cm，掉头前移约 54.4 cm，均完成原请求角度后保持停车。原办公室三项未触发调整分支，仍直接原地转向。完整证据及源码哈希见 `artifacts/turn-adjustment-20261016/verification.json`。
