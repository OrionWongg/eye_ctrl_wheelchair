# 眼动遥杆轮椅：人工方向控制与有限避障辅助

日期：2026-10-12  
状态：软件与 Gazebo 仿真版本已实现，实机尚未验证。实现与实验记录见 [`wheelchair_shared_ws`](../wheelchair_shared_ws/README.md)。

## 1. 项目目标与边界

用户通过眼动像使用遥杆一样控制轮椅，系统根据障碍物限制危险动作，并在明确边界内提供绕障辅助。用户始终决定运动是否继续、期望方向以及何时停止。

本阶段不实现目的地导航，不把眼睛朝向当成空间目标点，不需要先实现 SLAM 或完整 Nav2 导航。规划器内部可以使用短期轨迹预测，但不得在用户停止、改变方向或输入失效后继续执行旧计划。

当前底盘按固定档位动作建模：前进、后退、左转、右转、停止，不能任意设置线速度或角速度。本阶段眼动只开放前进、左转、右转、停止；后退不用于自动脱困。左右先按原地旋转建模，实机运动语义需后续确认。未验证前不允许前进与转向组合执行。

### 控制权规则

- 用户 STOP、眼动失效、指令过期、故障停车优先于所有规划动作。
- LEFT/RIGHT 表示明确转向；不允许为了避障反向旋转或自行前进。
- FORWARD 表示希望继续向前；基础模式只允许前进或停车，辅助模式可在有限角度内选择安全侧偏。
- 无安全动作时停车，不默认倒车，不通过大幅绕行自行寻找出口。
- 安全层停车不能被旧眼动运动状态自动解除；需要恢复确认。
- 用户可看到/听到当前意图、执行动作和介入原因。

## 2. “短期意图 + 离散动作规划”是什么意思

眼动模块只表达“现在想前进/左转/右转/停止”，并周期更新这个意图。意图有有效期，不是一次下达后无限执行的任务。为了适应眨眼和自然扫视，眼动意图经过状态机处理，不直接逐帧映射瞳孔位置。

规划器收到意图后，从真实可执行的固定动作中挑选最符合该意图且安全的动作。规划器可以预测未来几步，但只授权短时间的当前动作；下一周期重新检查传感器和意图。

例如，用户希望前进：

1. 前方畅通：保持 FORWARD。
2. 前方障碍、基础模式：STOP，并提示被阻挡。
3. 前方障碍、辅助模式：如有限左偏后能前进且符合辅助范围，先停车，再执行一小段左转；随后依据最新意图重新决定是否前进。
4. 用户此时请求 RIGHT：丢弃先前左侧候选，按安全转换过程处理 RIGHT；右转不安全则 STOP。
5. 用户停止或信号中断：取消全部候选，不继续完成绕障。

这里的“短期”是授权和预测范围有限，不是用户必须每隔几百毫秒眨眼，也不是按开停占空比制造低速。

## 4. 系统结构与模块归属

```text
EYETLE 检测
    ↓
眼动意图状态机 [Agent A]
    ↓ /wheelchair/intent
离散动作规划 + 最终安全检查 [Agent B]
    ↑ 雷达/障碍表示、真实 odom、执行器状态
    ↓ /wheelchair/action_safe
离散动作执行器 [Agent B 先实现仿真版本]
    ↓
固定档位仿真底盘 / 后续 BLE 实机适配器

规划和执行状态 → /wheelchair/control_status → 眼动状态机与用户反馈
```

眼动模块不能直接发布底盘命令。最终只有执行器能控制底盘。键盘调试输入也必须经过意图仲裁和相同安全链路，不得绕过防碰撞。

## 5. 共享 ROS 接口约定

由 Agent B 先创建独立的 `wheelchair_interfaces` ROS 2 接口包并固定枚举；Agent A 使用相同定义。建议独立工作空间 `/home/whill/wheelchair_shared_ws`，复用旧项目算法，不直接破坏现有演示入口。下面是接口字段要求，实施者可按 ROS 2 msg 语法落地。

### `/wheelchair/intent`：`ControlIntent`

| 字段 | 含义 |
|---|---|
| `header` | 产生时间；方向按机器人本体语义表达 |
| `session_id`、`sequence` | 区分生产者重启和旧消息，拒绝乱序/重放 |
| `command` | STOP=0、FORWARD=1、LEFT=2、RIGHT=3 |
| `enabled` | 用户运动授权是否有效 |
| `valid` | 眼动输入与标定是否有效 |
| `ttl_ms` | 有效期；接收方另外设置最大允许值 |
| `reason` | 停止、失效或状态改变原因 |

建议初始发布 20 Hz、有效期 250 ms，均为仿真初值。周期重发不能让失效检测数据变新；Agent A 必须监测眼动源数据年龄。旧 Float32MultiArray 无源时间戳，接入阶段只能按到达时间判断，应采用最新消息优先的小队列；后续为检测输出增加采集时间和序号，保留旧话题兼容性。

双眨眼只是修改授权状态；眼动模块随后持续发布短期有效意图。STOP 无需等待双眨眼或运动授权即可生效。

### `/wheelchair/action_safe`：`DiscreteAction`

| 字段 | 含义 |
|---|---|
| `header`、`session_id`、`sequence` | 消息时间和执行流标识 |
| `intent_session_id`、`intent_sequence` | 关联来源意图，便于取消与日志 |
| `action` | STOP=0、FORWARD=1、LEFT=2、RIGHT=3 |
| `ttl_ms` | 这次动作授权的有效期，不是整个规划的持续时间 |
| `reason` | USER_REQUEST、ASSIST、BLOCKED、STALE、FAULT 等 |

执行器接收的是当前动作状态，不是可以无限排队的任务。连续收到相同动作只续期，不反复释放/按下。STOP 或新方向使旧的待执行转换失效；不得把整个规划序列提前发送到串口队列。

建议初始动作发布 20 Hz、有效期 150 ms；需结合执行器最坏时延调整。消息有效期、允许观测年龄、执行延迟都必须计入停车预算，不能独立随意调大。

### `/wheelchair/control_status`：`ControlStatus`

包含：请求意图、当前执行动作、状态 PASS/ASSISTING/BLOCKED/FAULT、原因、`requires_rearm`、当前会话标识。命令采用 volatile、keep-last 小队列，不保存历史运动命令供新订阅者执行。

阻挡/故障后采用两步恢复：Agent A 清除运动授权并发送禁用的 STOP；Agent B 观察到该状态、且恢复条件满足后回报可重新授权；用户再次双眨眼后才开始新运动。仅有持续 FORWARD 心跳不能解除停车。重启和重连默认禁止运动。

超时看门狗使用单调时钟，消息源时间用于检测陈旧输入；仿真时间回跳、暂停恢复或 session 改变时使旧授权失效。真实眼动接仿真时明确统一 ROS 时间配置，不能混用墙钟和 /clock 计算源时间差。

## 6. Agent A：眼动意图模块实施任务

### 状态机

- DISARMED：启动默认状态；注视不导致运动。
- ACTIVE：双眨眼确认后进入，持续输出当前意图。
- BLOCKED：安全层要求重新授权；取消当前运动，显示原因。
- INVALID：未标定、信号失效或超时；立即输出禁用 STOP。

ACTIVE 中，正中为 FORWARD，左侧为 LEFT，右侧为 RIGHT。方向需稳定停留和阈值滞回：先采用 250 ms 停留、进入阈值 0.25、退出阈值 0.15 作为可调仿真初值。左/右持续注视对应持续转向请求；转回正中并稳定后请求前进。不要沿用“固定一秒转向脉冲”，因为这与本次遥杆语义不同。

正常短眨眼不切换方向，不重新启动运动；在有限眨眼窗口内保留上一个已确认意图，达到长闭眼阈值立即 STOP。源输入明确 invalid 时直接 STOP，不用眨眼宽限掩盖跟踪丢失。停止路径不经过方向停留滤波。

保留当前长闭眼约 650 ms 和最大单次运动 5 s 作为初始设置；5 s 到期后重新确认。它们是可用性实验参数，不代表实机安全阈值。禁止信号恢复后自动恢复 ACTIVE。

### 交付

1. 独立、可单元测试的意图状态机，不依赖 turtlesim。
2. ROS 包装节点、参数文件、模拟眼动输入工具。
3. 显示/语音反馈接口：方向、启用状态、阻挡、失效；先完成可查看的状态输出。
4. 保留原检测、标定和演示功能。
5. README：启动、话题、状态转换、参数语义及已知限制。

### 验收

- 停止状态随意看左右不启动；单眨眼不启动，双眨眼可确认。
- 左右阈值附近抖动、短暂扫视不会频繁改向。
- 持续左右注视、回正行为符合上面定义。
- 长闭眼、invalid、源超时、最大时长到期均停止并清除授权。
- 安全阻挡后旧 FORWARD 不会恢复运动；需要新的用户确认。
- 所有测试通过合成事件和录制数据完成，不自动连接真实轮椅。

## 7. Agent B：避障与离散执行模块实施任务

### 阶段 B1：人工直控 + 动作安全门

默认模式 `stop_only`：只放行用户请求动作或 STOP，不自动改变方向。先完成这一阶段并保留为对照组。

使用实际 odom 速度、可配置轮椅多边形轮廓、固定动作模型预测运动。每条候选必须覆盖当前动量、启动/转换延迟、执行授权持续期和最坏可接受停车过程。对线运动和角运动都建模，检查连续扫掠区域或有明确离散误差膨胀的采样轮廓。

STOP 表示发出停车指令，不能假设立刻静止。所有非零动作在放行时应具有可用的停车余量；若障碍突然进入停车包络，立即停车并报告风险，不能宣称物理上必然无碰撞。

直行危险则停车；原地旋转检查脚踏板、扶手等完整扫掠范围。轮椅尺寸未知时使用明确标记的仿真参数，不能继续使用 TurtleBot 的 0.18 m 半径代表轮椅。

### 阶段 B2：有限共享绕障

增加可切换模式 `bounded_assist`，不能取代 B1 对照模式。

- 仅对 FORWARD 开放自动侧偏；LEFT/RIGHT 仍仅放行原方向或停车。
- 搜索符合底盘能力的短动作序列，例如 STOP→LEFT→STOP→FORWARD；包括转换所需的停稳阶段，不生成任意连续速度。
- 预测范围可从 2–3 s 开始，在仿真中调参；最小动作持续时间取决于接口延迟与实测运动响应，不等于规划循环周期。
- 硬约束先剔除碰撞、未知区域风险、超出辅助范围和无法停车的候选，再评分；安全不能只是可被进度抵消的软惩罚。
- 评分兼顾用户期望方向、向前进度、间距和动作切换次数；加入滞回与侧向选择保持，防止左右振荡。任何保持规则都不能延迟 STOP。
- 只执行计划首段并滚动检查；用户改变意图立即取消旧计划。

辅助范围建议初值：相对当前这次前进意图的参考朝向最多偏转 15°，横向偏移最多 0.25 m，单次介入最多 2 s。全部可配置，属于待验证的交互约束。参考位姿在进入一次 FORWARD 意图时锁定，不得每周期按实际侧偏重新设定以绕过累计限制；用户明确转向后再进入 FORWARD 时才建立新参考。

超过范围、没有有用安全序列或无法判断用户希望绕哪侧时停车，请用户主动选择方向。持续小幅修正不得累积成无人确认的大绕行。这个模式可以辅助轻微绕障，但不承诺绕过所有正面障碍；大障碍由人决定转向。

### 感知

第一阶段可用已知仿真障碍或现有 LaserScan 建立闭环，再接 3D 点云。对机器人本体、地面和碰撞相关高度做显式处理；脚踏附近矮障碍和上方突出障碍需纳入碰撞表示。

未知/遮挡与确认自由区域分开表示。雷达、TF、odom 失效或过旧时停车。点云降采样、地面去除不能删除需要保护的障碍；本阶段若不实现落差检测，明确限制测试环境为平整无落差地面。

### 仿真执行器与实机适配边界

仿真执行器只接收固定档位动作，内部可转换成仿真器 Twist；不能因为仿真器支持任意速度就开放规划器连续调速。模型加入启动延迟、制动、左右转速差异和指令丢失。

连续同方向不主动停停走走。方向转换采用停止→确认低速/停稳→切换新动作，停车判定使用实际反馈和可配置阈值。长期未停稳则报告故障。

仿真先验证动作过期停车、节点退出、恢复不重启。后续 BLE 适配器需要实现完整的按住/释放/回中状态转换，并验证 App 的真实停止语义。主机进程死亡或通信中断后的释放保障需要执行端能力；仅增加主机看门狗不能保证失联后的实机停车。硬件尚未验收的功能必须明确标注为未实现，不伪造成功反馈。

### 交付与验收

1. `wheelchair_interfaces`、动作规划/安全模块、仿真动作执行器、参数与一键仿真入口。
2. 可独立使用键盘/脚本意图输入，无需等待 Agent A。
3. 场景：直行障碍、贴墙旋转、窄通道、轻微可绕障碍、左右均被堵、动态障碍、传感器中断。
4. 验证安全门拒绝危险固定动作，不能靠输出低速度“通过测试”。
5. 验证辅助范围的累计约束、明确转向不被反向替代、用户停止取消整个计划。
6. 验证重复消息不造成启停抖动，过期、重放、重启、断连和新意图不会执行旧动作。
7. README 和实验记录，记录假设、未验证的实机条件和可复现实验命令。

## 8. 联调顺序与数据记录

1. Agent B 固定共享消息与枚举，两个 agent 用模拟输入独立开发。
2. B1 仿真通过后，接入 Agent A 合成眼动，再接真实眼动摄像头。
3. 验证真实眼动 + 仿真轮椅的直控和停车闭环。
4. 开启 B2，对比相同场景下 stop_only 与 bounded_assist。
5. 硬件到位后测量动作响应、停止行为、最坏延迟及真实轮廓，再做 BLE 适配和受控实机验收。

记录眼动源时间、意图、候选/执行动作、介入原因、odom、障碍数据和连接状态。比较碰撞/最小间距、停止距离、停止延迟、用户转向次数、完成时间、介入次数和偏离用户方向的程度。

## 9. 给实施 agent 的范围要求

- Agent A 负责眼动检测之后的意图状态机及 ROS 包装，不修改避障和底盘驱动。
- Agent B 负责共享接口、避障、固定档位仿真和后续执行器接口设计，不修改眼动识别算法。
- 双方先对齐第 5 节接口；改变接口需同步另一方，禁止各自定义互不兼容的 String/Twist 协议。
- 本文授权范围为软件实现与仿真验证，不自动连接轮椅发运动命令，不修改或烧录 ESP32 固件。
- 不通过模拟系统键盘事件串接两个 GUI，不通过任意速度量化或高频启停绕开固定档位约束。
- 不把目标点自主导航、自动倒车脱困、复杂全局规划加入本阶段范围。

### 后续键盘交互调整

按用户后续要求，键盘正常操作改为 W/A/D 直接控制，取消初始 R 确认和键盘 5 秒上限；主动停车后可直接再次选择方向。障碍/故障停车仍锁定，R 恢复后再发新方向，持续按住 W 不能解除锁定。眼动双眨眼与 5 秒上限保持原方案。底层共享接口与安全链路不变。

### 窄走廊辅助恢复修正（2026-10-13）

新一次用户确认的授权不能继承上次已到期的辅助计时。禁用STOP握手完成、接受新的用户授权后重新给予单次2秒介入预算；连续心跳、单独STOP或无效输入不能续期。累计15°/0.25m的空间参考保留，仍仅在用户明确转向后再FORWARD时更新。重新确认后若没有满足剩余空间预算的安全辅助候选，停车并由用户选择方向，不自动解除空间限制。
