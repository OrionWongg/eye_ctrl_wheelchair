# Intent confirmation protocol v1 (implementation contract)

The five task-protocol messages (CandidateStatus, IntentEvent, InputHealth, IntentAck, TaskStatus) have `uint16 protocol_version=1` set by producers (ROS message default 0 is rejected). Header stamps use ROS /clock in simulation. Watchdogs and task elapsed budgets use monotonic time. Queues volatile depth 1, except event/ACK depth 10 (bounded retransmission). Only selected input source has subscriptions in task manager.

Topics: `/wheelchair/{eye|keyboard}/candidate` CandidateStatus, `/wheelchair/{eye|keyboard}/event` IntentEvent, `/wheelchair/{eye|keyboard}/health` InputHealth; `/wheelchair/intent_ack` IntentAck; `/wheelchair/task_status` TaskStatus. Manager is sole producer of `/wheelchair/intent` ControlIntent in intent_confirm; no legacy mux or legacy eye publisher in this mode. Existing safety_gate/executor remain.

CandidateStatus: header, protocol_version, source_session_id, sequence, candidate_id, candidate_version, kind (1 CONTINUE, 2 ADJUST_HEADING, 3 CANCEL), relative_yaw, stable, confirmable, ttl_ms, context_id, context_version, hint. Candidate semantic/version unchanged for heartbeat. ttl bounds each advertised validity; frozen transaction must keep its original expiry, not extend via new heartbeat. Publish withdrawal stable=false/confirmable=false when consumed or invalid. Manager caches consumed ID/version to reject new events for it. Candidate ACK/event delivery order: immediate withdrawal after confirm must not invalidate the in-flight submission; producer should keep confirmed candidate advertised until ACK (bounded by the original event and frozen-candidate deadlines, at most 1.5 s by default), but mark consumed internally immediately. Candidate context matches TaskStatus context.

IntentEvent: header, protocol_version, source_session_id, event_id, kind, candidate_id/version, context_id/version, relative_yaw, ttl_ms (default 1500, manager max 2000). Retries preserve all fields including original stamp/event_id. Pending events first cause a disabled STOP. After fresh lower feedback and the stop transit/dwell window, candidate and original deadlines are revalidated. Only then is ACCEPTED sent, before executor startup; expiry while waiting produces REJECTED. CANCEL kind=3 bypasses candidates and can invalidate same-tick pending confirmations; new session cannot motion until disabled STOP/health handshake.

InputHealth: header, protocol_version, source_session_id, sequence, source_valid, source_age_ms (float64, NEVER refreshed by timer), sample_sequence, reception_timed, ttl_ms (250). Optional stamped EyeSample `/eye_tracking/samples`: header is source SYSTEM/WALL clock (oldest camera read-completion time, not hardware exposure, mapped from the capture thread monotonic clock), source_session_id, sequence, horizontal, closed, valid. Legacy `/eye_tracking/signals` reception timing only. Source age preserved at health publish; manager requires header_age + source_age_ms < source_timeout and accumulates monotonic age when sample_sequence is unchanged. Event source and candidate source match healthy session.

IntentAck: header, protocol_version, manager_session_id, source_session_id, event_id, status (1 ACCEPTED,2 REJECTED), task_id, reason. Old retries can repeat cached ACK but NEVER start or refresh task. Sender retries same event at <=10Hz for <=event TTL; cancelled sender transaction must never retry. ACK valid only for matching source session and pending event.

TaskStatus: header, protocol_version, manager_session_id, sequence, task_id, source_session_id, event_id, state (0 IDLE,1 ACCEPTED,2 RUNNING,3 STOPPING,4 COMPLETED,5 BLOCKED,6 FAULT), kind, reference_yaw, target_yaw, remaining_time, remaining_distance, executed_action, reason, can_accept, context_id, context_version. Context id=manager session; version changes on semantic map changes, health/cancel/terminal invalidations, never mere heartbeat/normal refresh. can_accept means lower link healthy and authorization can be queued (may still be moving); not a guarantee of movement. Candidate generation requires fresh TaskStatus/context.

ControlIntent adapter extension (legacy defaults empty): task_id, task_kind (1 CONTINUE,2 ADJUST_HEADING), reference_x/y/yaw, target_yaw. Packet receives same optional fields. For CONTINUE reference fixed at confirmation pose; no acquisition of newly discovered side corridors after initial discovery. For ADJUST_HEADING target is locked only after stationary handshake to current yaw+relative_yaw. Task manager sends command FORWARD for CONTINUE, LEFT/RIGHT for ADJUST according to signed relative angle. Planner sees task identity to lock scope, closes finite heading loop and reports TASK_HEADING_COMPLETED only after actual stop; manager then terminates. Planner must not treat heartbeat as new task, and bounds goal using actual odom/braking and protected micro pulses. Existing safety TTL remains 150ms. Scoped task authorization angle default <=25deg from reference, fixed for each task.

Default task max 10s, accumulated odom path 3m. New events replace after STOP; ACK is not RUNNING. Completion/blocked/invalid/timeout clear queued task and hold disabled STOP; new event required. CANCEL priority: invalidate context + minimum source event watermark; a pre-cancel confirm must not be accepted later. Real source vs ROS time adaptation explicitly reception only for legacy signals. No real hardware.


ControlStatus additionally reports `task_id` so an earlier task's completion cannot finish a newer task. TaskStatus remaining budgets include actual braking feedback. The manager reserves worst-speed stopping distance and the next control period before the 3m/10s limits; it can stop early. Actual task success is separate from candidate confirmability and ACK.

Runtime interaction/input-source configuration is immutable. Stop and wait for settled feedback, then restart with the desired mode; restarting creates a new context and cannot revive an old event. Messages are local ROS simulation transport, not a hardware command API. Rebuild wheelchair_interfaces and restart its consumers together after upgrading.
