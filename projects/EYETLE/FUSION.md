## 用户操作

- 窗口自动居中，首次标定时置顶，大字中文提示和亮色圆点/箭头指示目标。当前屏幕 2560×1440 时，1280×800 内容区位于 (640,320)，正中圆点对应屏幕中心。
- 首次自动依次引导“正中→左边→右边→回正中”。头部不动，只看圆点；每步有约 1 秒准备期，之后连续稳定采集约 1.5 秒且至少 15 个样本。显示百分比和剩余保持时间。
- 眨眼、画面丢失或不稳定时暂停/重新积累当前步骤，绝不只按墙钟倒计时通过。左右无法区分时保持停止，提示重新采集。
- 成功后原子保存 `state/fusion-calibration.json`。相机、旋转、尺寸、模型匹配时，下次只显示正中确认，不再重复左右引导。
- 已就绪后双眨眼启动；长闭眼暂停；先睁眼再短眨眼恢复。标定期间持续输出无效/停止，不会带着未标定参数行驶。
- 按钮“重新确认正中”或 C：停车并确认中心。“重新标定左右”或 R：重新进行全部引导。保存失败可点“重试保存”。Esc / 退出按钮关闭，整套启动器可 Ctrl+C。

重戴造成大幅偏移时需要重新标定，不能宣称任何情况下只确认中心都正确。不同用户可使用 `--calibration-file state/user-fusion.json`；切换单眼/双眼会改变绑定，建议指定不同文件。

## 融合实现

1. RITnet 分割提供眼区和瞳孔中心，复用现有 TensorRT 引擎与闭眼规则。
2. PuReST 在 RITnet 已定位的眼区内独立跟踪瞳孔，ROI 改变或帧间隔异常时清空跟踪历史。没有眼区时禁用 PuReST 的全图回退，防止把其他暗区误当瞳孔。
3. 两种检测都使用完整纠正方向后的图像 x/宽度作为标定特征。PuReST 与可用 RITnet 瞳孔中心偏差超过图像宽度的 6% 时不采纳该 PuReST 结果。
4. 每个检测通道独立保存左/中/右参数，自动识别方向符号和左右增益。只选择三个方向均有有效稳定样本且最小分离 >0.008 的通道，每眼至少一个。
5. 先映射到统一 [-1,1] 方向范围，再按检测质量加权；同眼两个方法差 >0.5 或两眼差 >0.65 时输出无效。检测质量是工程评分，不是经过校准的正确概率。
6. 单种方法暂时丢失时，同眼可使用另一种已标定方法；双眼模式不在运行时自动切成单眼。严重冲突不靠平均消除。
7. PuReST 可靠地看到瞳孔，可补充 RITnet 的 unknown 为 open；闭眼专门由 RITnet 判断，PuReST 不再否决 RITnet 已确认的 closed（瞳孔跟踪器可能把闭合眼睑上的暗区当成瞳孔）。不会把 unknown 直接改成 closed。
8. 新融合入口现在传递独立眨眼事件：逐眼记录明确 closed 到 open 的时间，每眼 60～400 ms，开始/结束错开不超过 180 ms，且闭合区间必须重叠。未知最多桥接 120 ms，绝不单凭 unknown 创建闭眼事件。方向失效不抹掉事件历史，但运动立即停止，持续眼状态丢失或超时会取消事件。

可加 `--teyed-reference` 记录 TEyeD 原始输出作比较。它额外消耗推理时间，不直接加入方向融合。

## 原生算法来源与构建

PuRe/PuReST 来源：https://github.com/openPupil/PyPupilEXT ，固定提交 `a2999de1dee62243e3be764312556be2e4986068`。使用原 C++ 实现，最小 ctypes 接口位于 `tools/purest/`，没有用阈值算法冒充 PuReST。各源文件 SHA256 保存在 `tools/purest/sources.json`。

```bash
python3 tools/purest/build.py
```

依赖本机现有 g++ 和 OpenCV C++ 开发库。GUI 用 Python tkinter，无需额外桌面应用。PuRe/PuReST 源文件带非商业研究使用限制与引用要求，原许可及来源已保留在 `third_party/PyPupilEXT/`，不能据此宣称可直接用于商业产品。

## 验证

89 项自动化测试通过，覆盖：左右安装镜像补偿、三点不可区分拒绝、缺帧/闭眼打断采集、保存失败不启用、文件重载只确认中心、方法冲突/单眼丢失停车、独立闭眼保持，以及新融合到真实海龟控制器的双眨眼启用、左转、丢失停车。原 PuReST 本机库测试执行了合成椭圆跟踪和黑色遮挡拒绝，没有跳过。

窗口实际截图：`model-results/fusion-guide-left.png`，已检查中文和布局以及屏幕位置。

无显示硬件诊断使用 `--no-display --max-frames 90 --report ...`；该模式禁止发布控制并禁止自动采集/保存无人引导的标定，日志中的无效输出是预期行为。硬件结果见 `model-results/fusion-camera-final.json`：90 帧诊断，双眼处理耗时中位数约 74.0 ms、P95 118.6 ms；此模式按设计全部为无效控制输入。尚未完成带真实左/中/右动作标签的佩戴准确率验证，不能声称已解决所有侧视误判。


## 转向与眨眼更新（2026-10-16）

融合启动器的转向阈值从 ±0.25 提高到 ±0.55，回中重新允许转向的范围为 abs(horizontal)<0.25。引导窗口方向提示同步使用 ±0.55。这是标定后的归一化量，不是角度；仍是约 1 秒转向脉冲。

当前现场日志约 63 秒，标定成功后一直 DISARMED，原始 RITnet 有 8 条双眼 closed 记录，但发布的有效 closed 为 0。原因包括 PuReST 否决闭眼、双眼过渡超过原 100 ms 窗口。现已独立闭眼判断并将融合过渡窗口改为 200 ms。单眼闭合/未知持续超时仍不会被当作双眼眨眼；闭合时间不足 60 ms 仍可能被控制器忽略。

界面新增“已识别一次眨眼 · 请再眨眼一次”，日志增加 controller_blinks，便于区分检测与计数问题。新增真实控制器回归验证了两次含错开/短暂未知过渡的眨眼可以启用，小幅 ±0.4 输入不触发转向，明确方向可转向，持续丢失停车。验证文件：model-results/fusion-blink-fix-tests.log。测试通过不等于现场所有眨眼均能识别。


## 独立眨眼事件修复（2026-10-16）

先前 200 ms 双眼状态宽限保留为内部兼容逻辑，海龟融合入口已经不再依赖该逻辑的闭合交集计时。`tools/blink_events.py` 按左右眼分别匹配完整事件，采用 RITnet 开闭状态，PuReST 的方向回退不作为眨眼依据。至少需要每只眼明确闭合、随后睁开，单眼眨眼或持续未知不会启动。

融合检测器改用 `/eye_tracking/fusion_samples` 的 JSON 原子样本，携带方向有效性、是否睁眼、眨眼事件、长闭眼、源会话/序列与采集时间。启动器为控制器设置 `blink_input_mode:=events`。其他 `--teyed` / `--ritnet` / 演示入口仍用原三元素 signals 协议，不重复计数。

启动要求两次独立事件完成时间在 900 ms 窗口内。暂停恢复要求一次新事件。事件确认后必须当前双眼睁开、方向有效且帧新鲜才能运动；最多等待 250 ms，超过就丢弃本次启动/恢复授权。源端事件最多短暂重发 180 ms，控制器按会话、帧序号和事件 ID 去重。校准、长闭眼、急停、边界停车、持续丢失和消息超时都会取消待用授权；重启检测器需要重新双眨眼。

方向暂时无效时会先停车，但在短眨眼的完整过程被确认后可以完成对应的恢复。方向恢复本身不会让车自动运动。日志新增 `blink_event`、`blink_phase`、`gesture_continuity`、`long_close`，可区分每眼识别失败、事件匹配失败与方向尚未恢复。

验证：89 项自动化测试通过；其中实际控制器回调验证 50 ms 闭合交集但各眼各自闭合达标的双眨眼可以启用，方向失效期间第一次事件不丢，旧事件/重复消息不重复计数，授权过期不自动恢复，长闭眼、急停、超时仍停车。隔离 ROS_DOMAIN_ID=159 实际发布订阅测试得到两次事件、成功启用、无效输入停车，记录在 `model-results/fusion-event-transport.json`。没有启动真实运动程序，也尚未完成新的佩戴准确率验证。

**必须关闭旧检测器和旧控制器后，用 `./start_eye_turtle.sh --fusion` 重启整套程序。** 单独重启检测器而继续使用旧控制器不会连接到新事件通道。标定参数无需重做。

界面反馈订阅改为只保留最新一条，避免检测帧率低于控制器反馈频率时排队，导致眨眼计数和控制状态显示滞后。
