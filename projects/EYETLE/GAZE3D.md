# 三维眼动估计（2026-10-14）

默认流程已改为：RITnet TensorRT 分割 → 完整图像坐标下的瞳孔椭圆 → pye3d 0.3.2 三维眼球朝向 → 单点正前方参考 → 原有控制器。

这是自动拟合眼球 + 单点个体参考，不是完全免标定。它替换原来的“瞳孔横坐标 + 左中右三点映射”，不修改现有控制状态机、意图确认方式、急停及底层保护。

## 启动

```bash
cd /home/whill/projects/EYETLE
./start_ritnet.sh --eyes left               # 预览和眼动信号，不启动控制器
./start_eye_turtle.sh --ritnet --eyes left  # 海龟
./start_eye_turtle.sh --gazebo --eyes both  # 现有轮椅仿真入口
```

1. 戴好眼镜，缓慢看左、右、上、下，让模型获得不同角度的瞳孔观测。这不是按点标定，不需要 A/D，但拟合必须有视角变化。
2. 观察每只眼的 `3D_READY` 提示。启动至少需要约 2 秒有效建模数据，实际可能更久；一直盯着一个点无法充分拟合眼球。
3. 第一次使用，头朝前、眼睛看正前方，按 **S**。等待 0.4 秒后采集 60 个连续有效稳定样本，自动保存。无需左、中、右依次采样。
4. 保存后按当前控制器的既有交互规则操作。图像窗口里的状态来自实际控制器。
5. 后续启动自动读取中心参考，但仍会重新拟合眼球；模型未稳定时始终发布 `valid=false`，不会因为读到文件就允许行驶。

`S` 随时重采中心；`C` 清空本次运行中心，等待重新按 S；Enter 重试失败的保存。采样过程中有效性被撤销，旧文件保留至新中心成功保存。`--no-display` 可使用已保存参考，无参考时只发布无效信号。

## 眼镜移动时

- 周围皮肤/背景的光流会排除眼睛区域，检测明显图像平移、旋转或缩放。检测到移动后暂停有效输出。初始化期间保留观测，避免反复清空；已稳定模型在移动停止至少 0.7 秒后执行一次重新拟合。
- 三维眼球位置异常变化、模型生理范围异常、瞳孔重投影偏差过大、输入过期以及双眼方向差异过大，同样禁止有效输出。
- 小幅平移后尝试自动拟合并复用中心；明显旋转后会提示重新看正前方按 S，因为相机轴与头部正前方的关系改变了。
- 光流需要周围有纹理；它不是精确的眼镜姿态传感器，不能保证发现所有移动。单点参考不能消除所有镜架旋转误差。
- 连续闭眼最多沿用最近有效三维状态 1.2 秒，仅供原有眨眼/长闭眼检测使用；没有可靠开眼历史时不能用闭眼启动控制。

稳定门限和位移门限属于初始工程值，未完成实际佩戴移位准确率验证。不得把合成几何误差或分割置信度当作实际视线准确率。

## 文件和参数

新参考文件：`state/ritnet-center-3d.json`。按 USB 位置、图像旋转/尺寸、RITnet 模型哈希、三维模型版本、焦距和方向配置绑定；原来的 `state/ritnet-calibration.json` 保留，不转换、不覆盖。

```bash
./start_ritnet.sh --eyes left --center-file state/user-center-3d.json
./start_ritnet.sh --eyes left --recalibrate
# 对照旧算法，继续使用原来的三点标定：
./start_ritnet.sh --eyes left --gaze-method legacy --calibration-file state/ritnet-calibration.json
```

- `--gaze-span-deg 25`：偏离中心 25° 映射至 ±1；实际控制器方向阈值仍由控制器配置决定。
- `--left-gaze-sign -1 --right-gaze-sign -1`：默认符合这副眼镜之前标定的左右方向。更换安装方向后需在预览检查符号，看左应为负、看右应为正。
- `--camera-focal-px`：覆盖完整图像分辨率下的焦距。默认用资料中的**对角线 80°**和图像尺寸推算，640×480 时约 476.7 像素，假设主点居中、方形像素、无畸变。这不是实测相机内参；要进一步提高精度仍需一次硬件内参/畸变标定及对应矫正支持。
- 90°/270°旋转会交换模型分辨率；ROI 移动、缩放不改变三维模型的相机坐标。

### 本机验证记录

- 51 项 EYETLE 自动化测试通过。
- 隔离 ROS 域、无控制器的真实双摄像头检查收到 121 条消息，未确认中心时全部 `valid=false`。
- 单眼带预览短测约 24.7 帧/秒；双眼无预览短测约 20.2 帧/秒。相机和实时负载会影响结果，尚不构成持续性能保证。
- 实际相机短测结束时模型仍为 `3D_UNSTABLE`，未完成佩戴者配合的充分转眼建模及中心确认，尚不能确认现有相机安装能稳定拟合。模型不稳定时系统保持停止，不能绕过门限强行行驶。
- 尚未验证真实佩戴移位后的准确率，也未进行实车试验。测试程序均已退出。

### 持续 UNSTABLE 诊断修正

现场 15 秒诊断观察到 16 次移位事件；旧实现每次都重置模型，造成初始化被反复打断。现已改成初始化不被光流清空、稳定模型等待移动结束后单次重新拟合；光流必须具有至少三个图像象限的空间支持，减少局部眼睑运动误报。

另外实际拟合仍出现负的眼球深度/瞳孔直径及超出 pye3d 生理范围的结果。修正重置逻辑不能保证这些输入已经能稳定拟合，当前不放宽有效性门限。每两秒输出 `GAZE3D` 诊断，包括明确的异常原因、眼球中心、瞳孔直径、模型置信度和移位次数。

### 固定注视退回初始化的修复

用户保存的 `model-results/gaze3d-live.log` 含 46 条周期诊断：2 条模型范围异常、8 条 READY、34 条混合 WARMUP/SHIFT 提示、2 条闭眼时模型未就绪。原实现把视线覆盖度作为持续条件，最近150帧看同一点后会再次要求扫视。已改成首次成功拟合后保留覆盖度，只有模型重新拟合时清除；新增“扫视建模后持续定睛超过150帧仍保持就绪”的回归测试。

诊断现区分 WAIT_MOTION、WAIT_EYE_SWEEP、WAIT_CENTER_STABILITY，并记录短期眼球中心离散度和观测数量。光流增加往返一致性检查，平移按图像中心计算。原生理范围、重投影和输入超时保护保留；52项测试通过，实际抗移位准确率仍需验证。
