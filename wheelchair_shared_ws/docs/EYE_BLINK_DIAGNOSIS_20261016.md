## 复现与修改

1. **帧龄超时误当成手势中断。** 旧适配器在旧帧采集年龄达到 250 ms 时把停车屏障推进到当前接收时间。处理延迟 180 ms、采样间隔 100～140 ms 时，下一张帧仍新鲜，但旧帧已超时；新眨眼起点早于被推进的屏障，被误拒绝。新增回归在旧实现失败，报 REJECT_BEFORE_STOP，修复后通过。

   当前仍在 250 ms 帧龄限制下停车，仅保留有限手势历史。接收连续静默超过 400 ms 才触发独立手势 watchdog，与小乌龟的到达超时一致。新事件仍须有源端连续证据、合法时间和当前有效睁眼；授权最多保留事件结束后 250 ms。急停、真正手势丢失、检测源变化及长闭眼仍清除授权。陈旧样本的屏障按采集时间设置，时钟异常按本地时间设置。

2. **短闭眼被同时作为设备故障。** 原健康字段直接复用了运动有效性。现在连续跟踪到的短闭眼仍立即发 STOP、运动权限为 false，但设备健康可以为 true。丢失、坏样本和帧超时仍健康无效。避免正常眨眼额外触发 INPUT_HEALTH_TIMEOUT。

3. **旧导航状态清掉新恢复事务。** 方向管理器完成停车／启动交接前，可能仍发布上一任务的 STOPPED/BLOCKED。旧接口 context 改变会清除待应答事件。融合模式现在等待 ACK 时保留事务，仍受 ACK 超时、拒绝、输入、时钟与管理器会话保护；底层安全由管理器执行。ACK 后的新 BLOCKED 仍立即暂停。

这些修改针对已复现的接口时序问题，没有放宽闭眼分割、60～400 ms 眨眼时长、双眼配对或 unknown 阈值。目前没有数据证明放宽这些阈值能解决本次问题。
